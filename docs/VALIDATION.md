# 验证与测量

测试用于检查数据边界、延迟路径和可重复的合成画面质量，不能替代真实视频观看。字形覆盖率高，不代表中文完全不可辨认；掩膜外像素未变，也不代表掩膜没有误选背景。

## 测试环境

既有测量来自 Windows 11、AMD Ryzen 7 5800H、Python 3.11 环境。OpenCV 限制为两个线程。ProPainter 研究使用 NVIDIA RTX 3060 Laptop GPU 6 GB；实时手动模式不使用该 GPU 推理。

0.2.0 发布检查从不含旧环境或旧报告的项目副本安装锁定依赖：**131 项源码测试、2 项发布包检查通过**，覆盖处理与呈现、模式切换、旧帧失效、通知合并、样式校准、配置读写与恢复、窗口尺寸变化、便携版依赖。源码和便携自检均额外使用随附 Noto 字体验证，不依赖本机微软雅黑。便携目录不存在时相应测试会跳过，因此首次源码检出的通过数可能不同。

完成源码安装后：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m subtitle_eraser --self-test
```

完整验证依赖 Windows 和部分原生接口；Linux/macOS 不是当前支持的完整验证环境。自检会初始化 Qt 和本地 OCR 模型，但不会证明某个实际播放器可捕获。

## 0.2.1 窗口与全屏回归

新增回归覆盖：真实 HWND 首次显示、缩放与隐藏再显示；100%、125%、150%、200% 的有效缩放率；包含侧栏的窗口切到视频全屏后的选区映射；场景不匹配时拒绝重定位；旧帧丢弃；同进程全屏窗口跟随及返回；校准字高随布局缩放。自检在可见桌面外显示自己的覆盖层并检查实际大小，不采集用户桌面。

下面的独立检查会短暂显示程序生成的测试播放器，经过真实 Windows Graphics Capture、工作线程和覆盖层，检查窗口放大、缩回、独立无边框全屏 HWND 和返回原 HWND。只捕获测试窗口，不操作用户播放器。它包含静态图形和测试文本，验证窗口链路，不代表 B 站动态视频的完整兼容性或中文字形质量。

```powershell
.\.venv\Scripts\python.exe -m subtitle_eraser --window-test --output outputs/native-transitions.json
# 便携版也支持：
.\SubtitleEraser.exe --window-test --output native-transitions.json
```

本机 150% 缩放、2560×1600 屏幕的源代码检查中，各次布局恢复约 0.2–0.8 秒。该时间从测试窗口变化开始，到正确尺寸的结果可用；不是稳态逐帧延迟，也不包含显示器扫描。切换期间允许短暂显示原文。

## 合成素材与指标

`subtitle_eraser/fixtures.py` 生成 12 秒、24 fps、288 帧素材：纯色背景、复杂纹理、人脸示意插画、快速运动、镜头切换、字幕换行。每段包含字幕消失间隔，并提供只去掉中文、保留英文的干净背景及精确中文字形掩膜。

既有测量使用本机 Windows 微软雅黑字体。源码提供 OFL 许可的 Noto Sans SC 作为字体回退，也可用 `SUBTITLE_ERASER_TEST_FONT` 指定字体文件；不同字体的轮廓和指标可能不同，应在比较时记录并保持一致。仓库不分发 Windows 字体。

| 指标 | 含义与限制 |
| --- | --- |
| 字形覆盖率 | 修补掩膜与真实中文字幕（包括描边）的交集 / 真实字形面积；不能判断剩余文字是否仍可读 |
| 背景 MAE | 已知遮挡位置上的平均绝对像素误差，越小越接近合成干净背景；不等同于人眼自然度 |
| 英文改动像素 | 手动模式通过英文位于选区外来保护；不是语言识别能力的证明 |
| 掩膜外改动像素 | 修补合成是否越过实际掩膜；正确值应为零 |
| 背景边缘外误选 | 排除真实字形及允许的 3px 扩张后仍被选择的像素 |
| 空白帧掩膜 | 字幕消失时是否仍修补背景或遗留旧字形 |
| 局部处理耗时 | 当前中文选区的候选提取和修补 CPU 时间；排除素材生成、评分、捕获、GUI 与显示器扫描 |

P50 是中位数，P95 是 95% 样本不超过的值。不得用局部处理耗时直接推算整个应用的屏幕帧率或光学端到端延迟。

## 复现入口

所有命令均在项目根目录运行，结果写入被 Git 忽略的 `outputs/`。

| 内容 | 命令 | 结果目录 |
| --- | --- | --- |
| 自动识别的离线质量基线、原图/轮廓/修补视频和报告 | `.\validate.cmd` | `outputs/validation/` |
| 无 OCR 手动模式速度与质量 | `.\.venv\Scripts\python.exe tools\manual_benchmark.py` | `outputs/low-latency/` |
| 校准与默认规则对比 | `.\.venv\Scripts\python.exe tools\calibration_benchmark.py` | `outputs/calibration/` |
| 换句时两种覆盖方式的模拟 | `.\.venv\Scripts\python.exe tools\transition_benchmark.py` | `outputs/transition/` |

`validation/report.html` 对应自动识别离线基线，不能作为手动低延迟模式的性能报告。动态对比按素材帧率播放，并非实时处理录屏。切换模拟使用预设的延迟时序，只验证透明度是否让底层新字透出，不测真实显示延迟、漏检或修补质量。

## 校准对比的既有结果

以下结果是 2026-10-21 的合成测试；每种尺寸分别处理 288 个源帧，默认与校准模式交替执行。每段首帧模拟一次笔画点击，切换到黄字段时重新校准。真值只用于选取这个模拟点击和评分，不传给实际修补算法。

| 源画面 / 实际选区 | 默认有字帧 P50 | 校准有字帧 P50 / P95 | 默认 / 校准覆盖率 | 单次校准 P50 |
| --- | ---: | ---: | ---: | ---: |
| 960×540 / 768×91 | 10.40 ms | 10.14 / 12.48 ms | 99.44% / 99.23% | 1.65 ms |
| 1440×810 / 1152×138 | 21.48 ms | 19.96 / 25.63 ms | 99.44% / 99.36% | 2.56 ms |

两种模式的英文改动、掩膜外改动、3px 边缘以外背景误选和空白帧掩膜均为零。校准后颜色条件更窄，覆盖率轻微下降，背景 MAE 也略增；本样例不能证明校准提高修补自然度，因此校准是可选调整。第一次校准还可能包含初始化成本，既有 960 测试单次最大值约 20.34 ms。

运行校准脚本会生成 `metrics.json` 和每种尺寸的逐帧 JSON，包含环境、时序范围、每段样式、耗时和质量指标。应同时保留这些定义，不能只摘取最好的一帧时间。

## 可选的 ProPainter 比较

依次运行 `setup.cmd`、`validate.cmd`、`setup-research.cmd` 和 `research.cmd`。研究环境独立于桌面环境，且部分研究依赖未完整锁定；复现实验时记录实际版本。下载、GPU 驱动、权重来源和许可也应一并检查，详见 [第三方说明](../THIRD_PARTY.md)。

既有实验在三个 576×160、24 帧的一秒合成片段上执行，使用相同字形掩膜。完整离线流程约需 19.6–21.7 秒/片段，包含模型初始化和编码；并非纯推理速度。该次 PyTorch 分配显存峰值约 949 MiB，不等于系统全部显存用量。

ProPainter 在纯色、运动片段降低了误差，在人脸示意片段误差更高，未稳定优于 OpenCV。输出经过原始掩膜再次合成，掩膜外像素保持不变。该路线是效果与资源成本研究，**不支持实时观看**，也没有被接入实时覆盖层。

## 发布前验证

1. 从干净源码目录按锁文件安装，执行测试与源码自检；记录跳过项，不把未构建的便携测试视为已通过。
2. 运行 `build.cmd`。从项目以外目录启动 `dist-calibrated/SubtitleEraser/SubtitleEraser.exe --self-test --output <可写结果路径>`，检查 Qt、OCR 模型、透明度、校准及配置自检。
3. 完整解压待分发 ZIP，再运行其中的 EXE；检查 `_internal` 和许可证材料齐全。
4. 手动试用普通窗口、缩放、最小化、前台切换、暂停/原图、框选、校准与配置恢复。窗口大小变化必须使旧范围失效。
5. 使用获准分享的视频样本检查浅色衣物、真实人脸、两行字幕、长短句交替、快速运动和切镜；记录误选、残留字、接缝及可见时差。

目前没有完成对 B 站及其他实际网站/客户端的系统兼容性验收，不能把合成结果当作网站支持承诺。问题报告建议说明 Windows 版本、播放器、窗口尺寸、是否全屏、字幕样式及所选处理方式；分享录屏或日志前检查私人内容。

## 0.2.2 全屏字幕修复检查

源码回归覆盖放大 1.5/2/3 倍的真正中文字符与一起放大的黑色描边、直接全屏选区、同排两端缺字、背景亮物体拒绝、英文边界保持、4K 缩略图中的细选区、确认时尺寸变化及切回后的恢复。此前固定 2px 描边的多分辨率样例不足以暴露真实视频放大后的黑边，新增检查对整张字幕图及真值一起缩放。

在本机微软雅黑、纯色合成背景、同一 2 倍放大样例上：0.2.1 黑色描边覆盖率约 43.8%，0.2.2 跟随路径为 100%，直接全屏路径约 99.8%；7 次重复的局部处理 P50 分别约 25.3 / 12.2 / 27.9ms。这些数值不含窗口采集、行宽检查、界面和显示器延迟，也不代表真实影片的自然度或所有字体的准确率。

下面的原生检查短暂打开自己的中文测试播放器和真正的框选对话框，在框选期间主动改变播放器尺寸，确认后返回 2560×1600 全屏，要求中文掩膜覆盖超过 99% 且覆盖层实际可见。它只捕获生成的测试窗口；应在可交互 Windows 桌面运行。Windows 若拒绝测试窗口获取前台，检查会失败，不把仅有处理结果当作显示成功。

```powershell
.\.venv\Scripts\python.exe -m subtitle_eraser --selection-test --output outputs/native-selection.json
# 便携版也支持：
.\SubtitleEraser.exe --selection-test --output native-selection.json
```

尚未用本次用户的 B 站影片完成复验；这里的真实窗口链路与合成中文字形检查不能代替该影片的人工验收。

## 0.2.3 真实快捷键链路检查

`tools/check_fullscreen_hotkey.py` 或便携版 `--hotkey-test` 显示生成的测试播放器，并销毁原始窗口、切换到新的全屏窗口。等待界面准备后，由操作者向全屏测试播放器实际按下启用的组合键；程序检查注册热键消息、框选对话框实际显示、自动取消后覆盖层恢复。检查 120 秒超时退出，不会注入输入或捕获其他应用。

此次交互验证使用 Ctrl+Alt+Shift+R，记录到一次真实热键消息，框选窗口显示，旧 HWND 销毁后的全屏跟随与取消后的覆盖恢复均通过。此前直接调用 select_region 的检查不能作为真实按键链路通过的证据。

## 0.3.0 界面布局检查

`tests/test_comparison_ui.py` 检查控制与对比窗口的独立生命周期、小窗口中的三栏完整显示与单图放大、控制窗口最小化后的对比刷新、冻结期间继续消费处理结果、切换冻结的同一帧及快照导出。检查使用内存里的合成帧，不捕获其他应用。

运行以下命令可渲染应用自己的窗口并输出 PNG 和 `layout.json`。测试窗口设置为不显示到桌面，不发送键盘/鼠标输入，不注册真实快捷键或保存播放器设置。JSON 记录实际 DPR、窗口逻辑尺寸和可用工作区；PNG 是界面渲染检查，不是实时处理速度报告。

```powershell
$env:QT_SCREEN_SCALE_FACTORS = '1.5'
.\.venv\Scripts\python.exe tools\check_ui_layout.py --output outputs/ui-layout-150
```

分别使用 `1.25`、`1.5` 和 `2` 检查其他比例。在本身有缩放的 Windows 桌面上，100% 检查可在单独测试进程中使用 `QT_ENABLE_HIGHDPI_SCALING=0`，以记录中的实际 DPR 为准。不要把这些测试环境变量写入日常启动脚本。
